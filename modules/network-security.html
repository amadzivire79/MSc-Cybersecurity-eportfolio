Module Overview

Developing Practical Network Security Capability

The Network Security module enabled me to develop a stronger understanding of how networked systems can be examined, assessed and protected against cyber threats. My practical work focused particularly on network reconnaissance, vulnerability scanning, service enumeration, cryptographic weaknesses and the interpretation of security findings.

A significant element of the module involved performing a technical security assessment of the Altoro Mutual online banking training environment. The assessment was conducted within an isolated virtual machine environment using security tools including Nessus, Nmap and OpenVAS.

I also conducted reconnaissance using WHOIS, traceroute, dig and nslookup. Combining these tools enabled me to move beyond individual scan results and build a broader picture of the target infrastructure, services, DNS configuration and potential attack surface.

04

Technical Analysis

Key Security Findings

My Altoro Mutual assessment identified several security weaknesses illustrating how insecure configurations can increase the attack surface of internet-facing systems.

MEDIUM RISK

Missing HTTP Strict Transport Security

Nessus identified the absence of HSTS, increasing the potential for downgrade and SSL-stripping attacks against users accessing the application.

CRYPTOGRAPHIC RISK

Legacy TLS and Weak Cipher Suites

The server supported outdated TLS implementations and weak cryptographic configurations, including CBC-based cipher suites and weak Diffie-Hellman parameters.

ATTACK SURFACE

Exposed Network Services

Services were publicly accessible on ports 80, 443 and 8080. Multiple exposed interfaces increase the number of potential entry points available to attackers.

CONFIGURATION

Dangerous HTTP Methods

HTTP methods including PUT and DELETE were identified. If insufficiently protected, these methods may permit unauthorised modification or upload of resources.

INFORMATION DISCLOSURE

Server Fingerprinting

HTTP headers exposed server information including Apache-Coyote and Apache Tomcat characteristics that could assist an attacker during reconnaissance.

DNS SECURITY

DNSSEC Not Enabled

Reconnaissance showed reliance on Akamai's distributed DNS infrastructure while DNSSEC was not enabled, representing an area for improved DNS integrity.

Security Improvement

Mitigation Recommendations

01

Strengthen TLS Configuration

Disable TLS 1.0 and TLS 1.1 and enforce modern TLS 1.2 and TLS 1.3 configurations with strong cipher suites.

02

Implement HSTS

Configure HTTP Strict Transport Security to reduce the risk of SSL stripping and protocol downgrade attacks.

03

Reduce Exposed Services

Review externally accessible ports and services and remove unnecessary exposure in accordance with the principle of least privilege.

04

Harden HTTP Configuration

Disable unnecessary PUT and DELETE methods and minimise disclosure of server and technology information.

05

Improve Vulnerability Management

Introduce regular scanning, patch validation, configuration management and continuous security monitoring.

06

Improve DNS Security

Consider DNSSEC and continuously review DNS configuration and infrastructure resilience.

Feedback & Development

Using Feedback to Improve My Work

💬

Learning from Assessment

A key lesson from the assessment process was the importance of moving beyond simply reporting automated tool output. Effective cybersecurity analysis requires findings to be validated, interpreted in context and related to genuine organisational risk.

I consequently focused on strengthening the connection between technical evidence, business impact, remediation and recognised cybersecurity frameworks. This improved the professional quality of my reporting and my ability to communicate technical issues to non-technical stakeholders.

08

Reflective Practice

Critical Reflection

This module significantly strengthened my understanding of vulnerability assessment as an analytical process rather than simply a scanning exercise. Initially, I was most confident with the technical tasks but found it more challenging to integrate legal, ethical and organisational considerations into a cohesive security assessment.

One of the most valuable aspects of the work was learning to synthesise information from multiple sources. Combining traceroute, DNS and WHOIS outputs with Nmap, Nessus and OpenVAS findings enabled me to build a more complete view of the target environment. It also reinforced the importance of cross-checking automated findings rather than relying on a single tool.

I encountered situations where scan results initially appeared unusual. For example, several routers did not respond to traceroute probes and no MX records were returned for the target domain. Further analysis demonstrated that these observations did not necessarily represent vulnerabilities. Firewalls may intentionally suppress ICMP responses, while the absence of MX records was consistent with the site's function as a training environment.

This experience improved my judgement when distinguishing between genuine security weaknesses, normal infrastructure behaviour and deliberate defensive controls. It also developed my ability to translate technical findings into clear, risk-based recommendations.

More broadly, the assessment demonstrated that network security involves more than technical controls. Legal authorisation, ethical conduct, governance and professional communication are integral to responsible cybersecurity practice.
